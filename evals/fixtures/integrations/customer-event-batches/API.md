# Customer event feed and delivery contract

These are fictional services for local HTTP mocks. Customers configure a feed base URL and bearer token, a delivery base URL and bearer token, an account ID and a check cadence. No live endpoint or credentials are provided.

`GET /accounts/{accountId}/events` accepts optional opaque `cursor` and returns `200 { "items": [{ "eventId": "evt/1", "customerId": "customer/A", "sequence": 10, "kind": "order.updated", "payload": { "orderId": "o-1" } }], "nextCursor": "opaque-next" }`. The final page has `nextCursor: null`. A page has at most five events. Items are in ascending `sequence` order across all pages for an account; each event ID and sequence is unique. Customers can be interleaved. A cursor refers to the next unread page, and replaying a cursor returns the same page. Account IDs and cursor values are opaque URL values. Source errors return non-2xx.

`POST /customers/{customerId}/events:batch` accepts JSON `{ "events": [{ "eventId": "evt/1", "sequence": 10, "kind": "order.updated", "payload": { "orderId": "o-1" } }] }`, a bearer token and an `Idempotency-Key` header. Each request must contain one to three events for the path's customer, in ascending source sequence. The path customer ID must be URL-encoded. `200 { "accepted": ["evt/1"] }` confirms every submitted event atomically; the response lists all submitted event IDs. Partial acceptance does not occur. Repeating the same key and body returns the same acceptance. Reusing a key with a different body returns `409`. The integration may choose any stable key for an identical group. A `503` confirms nothing, and non-2xx errors are not success.

This service preserves order only when requests for a given customer arrive in order: do not submit a later group for that customer before its earlier group is confirmed. Different customers have no relative-order requirement. An accepted group may be replayed safely. The source can hold a long backlog; the integration must make continued progress without loading an unbounded history into one execution.
