# Ticket source contract

This fictional source is available only through local HTTP mocks; no live account or credential is supplied. Customers configure a source base URL and bearer token separately from the archive. Send `Authorization: Bearer <token>` on source requests.

For reconciliation, `GET {sourceBaseUrl}/tickets/changes` accepts an optional opaque `cursor` query parameter. Without a cursor it begins at the oldest retained change, so a first run can backfill existing tickets. A successful page returns HTTP 200 `{ "items": [Ticket], "nextCursor": string, "hasMore": boolean }`, where Ticket has the webhook shape in API.md. When `hasMore` is true, fetch the next page with `nextCursor`. When false, retain `nextCursor` for a future scheduled check. A page may be empty despite `hasMore: true`; use `hasMore`, not item count, for continuation. Changes are ordered, and each cursor resumes after that page. A failed request does not advance the source cursor. Non-2xx statuses and network failures remain visible. The source offers no history before its oldest retained change.

For a customer queue chooser, `GET {sourceBaseUrl}/queues` accepts an optional opaque `cursor` query parameter. It returns HTTP 200 `{ "items": [{ "id": string, "name": string }], "nextCursor": string | null, "hasMore": boolean }`. Follow `nextCursor` while `hasMore` is true, even for an empty page. Queue IDs are opaque; use the IDs as configuration values and names as labels. A non-2xx status or network failure is a source error. There is no fixed queue list or unauthenticated discovery endpoint.
