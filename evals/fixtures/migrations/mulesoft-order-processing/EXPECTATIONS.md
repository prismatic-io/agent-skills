## Comparator policy

Run `python3 evals/fixtures/migrations/mulesoft-order-processing/check.py verify-source` to verify local source-file SHA256 hashes, independent fixture copies, and selected sample consistency checks. This is a source/contract check, not execution of Mule or DataWeave.

After a separately authorized subject run, use:

```sh
python3 evals/fixtures/migrations/mulesoft-order-processing/check.py compare --orders /path/to/generated/orders.json --report /path/to/generated/report.csv
```

It compares JSON structure with exact decimal numeric values and array order, preserving string whitespace and rejecting duplicate JSON object keys. JSON object key order, formatting, and numeric spelling such as `27.60` versus `27.6` are intentionally ignored. CSV header/column order, row order, and row count are checked; the three known report columns compare as finite decimal numbers. Quoting, newline style, and equivalent decimal spellings are formatting differences. Whitespace added inside a report cell and nonstandard numeric spellings such as underscores are rejected. Accepted numeric cell syntax is a signed or unsigned decimal (including a fractional form), optionally followed by a base-10 exponent. This is the comparator normalization policy, not a claim about every Mule CSV reader. The upstream Java test strips all whitespace; this comparator deliberately avoids hiding changed whitespace within meaningful JSON strings.

`python3 evals/fixtures/migrations/mulesoft-order-processing/check.py self-test` confirms the comparator accepts the original expected outputs and rejects a missing order, changed title whitespace, stringified price, incorrect report, and underscore-containing numeric text. Positive controls cover JSON numeric spelling and CSV exponent/newline formatting. These are comparator checks only, not additional source behaviors or migration results.
